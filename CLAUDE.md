## Project overview

Minimal example app demonstrating **Astro + React islands** deployed to **Webflow Cloud**, running on the **Cloudflare Workers** adapter. It's a starter/template repo (`hello-world-astrov01`), not a full application — expect a small surface area.

## Commands

| Command | Action |
| :------ | :----- |
| `npm install` | Install dependencies |
| `npm run dev` | Start the Astro dev server at `http://localhost:4321` |
| `npm run build` | Build the production site (`astro build`) |
| `npm run preview` | Build, then run `wrangler dev` for a local Cloudflare Worker preview |
| `npm run deploy` | Deploy via `webflow cloud deploy` |
| `npm run astro` | Run the Astro CLI directly (e.g. `astro add`, `astro check`) |
| `npm run cf-typegen` | Regenerate Cloudflare Worker types into `worker-configuration.d.ts` (`wrangler types`) |

There is no test suite or linter configured in this repo.

## Architecture

- **Rendering mode**: `output: "server"` in `astro.config.mjs` — pages/API routes run server-side on Cloudflare Workers via `@astrojs/cloudflare`, not statically prerendered.
- **Base path**: `base: "CLOUD_MOUNT_PATH"` is a placeholder substituted by Webflow Cloud at deploy time for the app's mount path under the parent Webflow site. Code that builds asset/link URLs (e.g. `src/pages/index.astro`, `src/layouts/Layout.astro`) reads `import.meta.env.BASE_URL` at runtime and strips a trailing slash — follow this pattern for any new internal links/assets so they resolve correctly when mounted at a sub-path.
- **React integration**: `@astrojs/react` is registered for islands, but React isn't yet used anywhere in `src/pages` — the sample interactivity (`src/lib/counter.ts`) is wired up via a plain `<script>` in `index.astro`, not a React component. A Vite alias swaps `react-dom/server` → `react-dom/server.edge` in production builds so React 19 SSR works on the Workers runtime without polyfilling `MessageChannel`.
- **API routes**: File-based under `src/pages/api/` following Astro's `APIRoute` convention (see `src/pages/api/hello.ts`). New endpoints go here as `export const GET/POST/... : APIRoute`.
- **Cloudflare bindings**: `wrangler.json` declares the Worker config (currently just static asset serving from `dist/client` and observability). `Env` in `worker-configuration.d.ts` is auto-generated by `npm run cf-typegen` — regenerate it after adding any binding (KV, D1, R2, secrets, etc.) to `wrangler.json`, and access bindings at runtime through `Astro.locals.runtime.env` (typed via `App.Locals` in `src/env.d.ts`).
- **Webflow Cloud**: `webflow.json` declares the framework (`astro`) for Webflow's deploy tooling; `npm run deploy` shells out to the `webflow` CLI.
